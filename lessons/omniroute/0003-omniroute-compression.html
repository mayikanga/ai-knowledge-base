    Token 压缩

    节省 95% 的秘诀

    OmniRoute 最实用的功能之一——内置 Token 压缩引擎，针对编程场景优化，平均节省 89% 的工具密集型会话 Token。更少的 Token = 更低的成本 = 更快的响应。

    为什么需要压缩？

    AI 编程工具的特点是工具调用密集——每次文件读写、搜索、git 操作都会产生大量 Token。这些 Token 中大部分是重复的、结构化的、对理解意图无帮助的内容。OmniRoute 的 10 引擎压缩管线专门解决这个问题。

    10 引擎压缩管线

    #引擎作用节省
    1Session-Dedup去除跨轮次重复内容~10%
    2CCR大块内容归档为检索标记~20%
    3RTK 🔥工具结果智能过滤、去重、截断60-90%
    4Headroom同构 JSON 数组的表格式压缩~30%
    5Relevance基于用户最近问题的句子评分~15%
    6Caveman基于规则的散文压缩 (~65-75%)~65%
    7LLMLingua-2机器学习语义剪枝~40%
    8Lite空白和图片 URL 修剪~5%
    9Aggressive总结 + 旧轮次渐进老化~50%
    10Ultra启发式剪枝 + 小模型辅助~75%

    🔥 RTK 是编程场景的杀手锏——对 shell 输出、测试结果、git diff、构建日志等工具结果，它能保留结构而大幅压缩体积。

    预设模式

    模式节省适用场景
    Lite~15%始终开启的安全默认
    Standard (Caveman)~30%日常编码
    Aggressive~50%工具密集型长会话
    Ultra~75%最大节省
    RTK60-90%Shell/测试/构建输出
    Stacked (RTK→Caveman)78-95%混合提示+工具日志

    代码块、URL、JSON 和结构化数据始终逐字节保留。

    配置压缩

    在组合中指定：

    omniroute combo create coding \
  --model auto/coding \
  --compression stacked

    按请求覆盖：在请求头加 x-omniroute-compression: ultra。

    通过仪表板压缩工作室可视化调整引擎顺序和开关。

    动手练习

    🎯 对比压缩效果

    1. 查看压缩统计

      在仪表板中找到压缩面板，查看当前节省率。

    2. 创建不同压缩模式的组合
      omniroute combo create test-lite --model auto --compression lite
omniroute combo create test-ultra --model auto --compression ultra
    3. 切换对比

      在 Claude Code 或其他工具中分别使用这两个组合，观察 Token 消耗的区别。

    关键要点

    • 10 引擎管线，从去重到语义剪枝，按顺序执行
    • RTK 引擎是编程场景的核心——工具输出压缩 60-90%
    • Stacked 模式 (RTK→Caveman) 可达 78-95% 节省
    • 代码和结构化数据始终无损保留
    • 可在组合级别、请求级别、仪表板中配置

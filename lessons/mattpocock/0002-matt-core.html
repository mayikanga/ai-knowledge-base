    核心技能实操

    Grill / TDD / Review 三板斧

    三个最常用的技能：/grill-with-docs（需求对齐）、/tdd（测试驱动开发）、/code-review（代码审查）。 这三个覆盖了"想清楚 → 写对 → 保证质量"的完整链路。

    /grill-with-docs：面试式需求梳理

    这是 Matt Pocock 最受欢迎的技能，解决"Agent 没做对"的根本原因——需求没对齐。

    💡 原理

    不直接让 agent 写代码，而是先让它面试你——追问需求的每个细节，直到双方对"要做什么"达成共识。

    它会做什么

    1. 追问你的需求，层层深入，不放过模糊之处
    2. 建立项目的领域模型（核心概念和术语）
    3. 更新 CONTEXT.md（项目共享语言文档）
    4. 生成或更新 ADR（架构决策记录）

    效果

    之前之后
    Agent 用 20 个词描述一个概念项目有统一的术语表，1 个词就够了
    每次会话 Agent 重新理解项目CONTEXT.md 让 Agent 快速进入状态
    变量/函数命名不一致领域语言驱动命名，代码自文档化
    Agent 消耗大量 Token 揣测意图需求对齐后 Token 消耗大幅降低
    🔑 CONTEXT.md 是 Matt Pocock 说的"这个仓库里最酷的技术"——一份共享语言文档，让 agent 理解项目的领域术语，少说废话。

    /tdd：红-绿-重构

    TDD 不是新概念，但让 AI 按 TDD 循环工作能大幅提升代码质量。 这个技能把"红-绿-重构"循环编码为 AI 的工作协议。

    流程

    🔴  RED — 先写测试（测试失败）
    让 agent 理解"什么算完成"

🟢  GREEN — 写刚好能让测试通过的代码
    不追求完美，只求通过

🔵  REFACTOR — 重构代码
    现在才优化实现，测试保证没改坏

    关键点：一次只做一个垂直切片——每次循环只增加一小块功能，测试通过后再继续。

    ⚠️ 常见错误

    让 AI 先写实现再补测试 = 错过了 TDD 的核心价值。

    /tdd 强制"先测试后实现"的顺序，这才是 TDD 的精髓。

    /code-review：双轴审查

    这个技能的特别之处是用并行 subagent 做双轴审查：

    轴审查什么由谁执行
    Standards 轴编码规范、Martin Fowler 代码坏味道一个 subagent
    Spec 轴功能是否按规格实现了另一个 subagent

    两个 subagent 并行工作，互不污染——审查结果再汇总给你。

    💡 这和 Claude Code 进阶 L3、L4 的关系

    你在 Claude Code 进阶课学过 subagent（L3）和 workflow 编排（L4）。 /code-review 其实就是一个实时的、轻量的 workflow——两个并行 agent 各审一个维度。

    Matt Pocock 用 subagent 做代码审查的思路，和你学过的 Adversarial Review 模式（L5）是一样的。

    动手练习

    🎯 跑一遍完整链路

    1. 需求梳理

      在 Claude Code 中输入 /grill-with-docs，然后告诉它你想实现的一个功能。体验它的追问过程。

    2. TDD 实现

      用 /implement 驱动 /tdd 来构建刚才需求中的核心逻辑。观察红-绿-重构循环。

    3. 代码审查

      实现完成后，运行 /code-review。看看两个 subagent 分别从标准和规格角度审查的结果。

    4. 对比

      对比"直接让 Claude 写"和"走完这三步"的输出质量差异。

    关键要点

    • /grill-with-docs = 面试式需求梳理，先对齐再动手
    • /tdd = 红-绿-重构循环，一次一个垂直切片
    • /code-review = 双轴并行审查，标准和规格各一个 subagent
    • 三个技能连起来 = 想清楚 → 写对 → 保证质量

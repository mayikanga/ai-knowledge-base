    /handoff：跨会话交接

    这是AI 开发中最容易被忽视但最关键的能力——一个会话的上下文怎么交给下一个会话。

    💡 场景

    你今天写到一半下班了，明天 Claude Code 新会话不记得昨天讨论了什么。/handoff 把当前会话压缩成一份结构化的交接文档，下个会话直接读取。

    它会生成什么

    • 当前状态 — 做了什么、到什么阶段
    • 未完成的工作 — 下一步要做什么
    • 关键决策 — 重要的权衡和选择
    • 注意事项 — 坑、边界情况、已知问题
    • 相关链接 — Issue、PR、文档引用

    和 CLAUDE.md 的区别

    CLAUDE.md/handoff
    用途项目级持久规范会话级临时交接
    内容编码规范、约定、配置当前进度、决策、待办
    更新频率偶尔改每次会话结束
    谁维护项目所有者AI + 你协作更新

    /wayfinder：跨会话大规模规划

    当一个任务明显超过一个会话能完成的范围时，Wayfinder 帮你把大块工作拆解为一系列"调查任务"（investigation tickets）。 每个 ticket 可以在一个会话内完成，完成后向下一个推进。

    工作流

    大目标（如"重构整个认证系统"）
  ↓
/wayfinder 拆解为调查任务：
  ├─ 任务1：分析当前认证流程
  ├─ 任务2：设计新架构方案
  ├─ 任务3：实现核心接口
  ├─ 任务4：迁移现有用户
  └─ 任务5：清理旧代码
  ↓
逐个解决，每个任务一个会话
  ↓
全部完成 → 目标达成
    💡 和 Claude Code Workflow 的关系

    你在 CC L4 学过 Workflow 编排（多个 subagent 并行）。Wayfinder 是相反的思路——把大任务纵向拆成多个串行会话。

    两者互补：Wayfinder 决定做什么顺序，Workflow 决定一个会话内怎么并行。

    /improve-codebase-architecture：架构保卫战

    Matt Pocock 引用 Kent Beck："Invest in the design of the system every day." 这个技能就是定期扫描代码库，找出设计深化机会。

    它能发现什么

    • 模块边界模糊 —— 哪些模块该拆分却混在一起
    • 接口过于宽泛 —— 哪些模块暴露了太多内部细节
    • 缺少抽象 —— 哪些重复模式可以提取为通用抽象
    • 依赖方向错误 —— 哪些模块依赖了不该依赖的

    生成一份可视化的 HTML 报告，然后让你选择从哪个改进点开始。

    ⚠️ 使用频率

    官方建议：每几天跑一次。不是每日必做，而是定期"体检"。

    搭配 /domain-modeling 一起用效果更好——先理清领域模型，再检查实现是否偏离。

    技能组合路线图

    这些技能不是孤立的，Matt Pocock 设计了清晰的调用链：

    新项目 / 新功能
  ↓
/grill-with-docs   ← 先对齐需求，建立 CONTEXT.md
  ↓
/to-spec           ← 把对齐后的需求写成规格
  ↓
/to-tickets        ← 拆成带依赖的任务
  ↓
/implement         ← 驱动 /tdd 实现
  ↓                  （每次迭代自动调 /tdd）
/code-review       ← 双轴审查后提交
  ↓
（下一个任务...）
  ↓
定期：/improve-codebase-architecture
       /domain-modeling
       /handoff（会话结束时）

    /to-spec 和 /to-tickets

    技能输入输出
    /to-spec当前对话讨论的需求结构化的规格文档（可发布到 Issue Tracker）
    /to-tickets规格或对话带阻塞依赖关系的 tracer-bullet tickets

    /to-tickets 特别之处：它生成的 ticket 之间标注了阻塞依赖（哪个 ticket 等哪个完成后才能开始），这对多会话规划至关重要。

    动手练习

    🎯 完整流程演练

    1. 规划一个大功能

      用 /wayfinder 规划一个你觉得需要 3+ 会话才能完成的功能。

    2. 结束后 handoff

      一个会话结束时运行 /handoff，生成交接文档。

    3. 新会话读取 handoff

      新会话中读取 handoff 文档，看看是否清晰。

    4. 架构体检

      在项目中运行 /improve-codebase-architecture，看看它发现了什么。

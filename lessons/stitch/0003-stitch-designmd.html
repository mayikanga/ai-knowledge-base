    DESIGN.md

    设计系统即代码

    L2 你学会了写好的提示词。但你有没有想过：每次写提示词都要重复一堆颜色、风格、字体信息，很烦？ DESIGN.md 就是解决这个问题的——把你的设计风格固化为一个可复用的标准文件，一次定义，到处应用。

    什么是 DESIGN.md？

    DESIGN.md 是 Google Labs 发起的一个开放标准，用 Markdown 格式描述设计系统的核心 Token——颜色、字体、间距、组件规则。 它和 Claude Code 的 CLAUDE.md 是同一个思路：把元知识写进一个标准文件，让 AI 工具理解并遵守。

    💡 类比

    CLAUDE.md 是给 Claude Code 看的项目规范 → 告诉 AI "代码怎么写"
    DESIGN.md 是给 Stitch 看的设计规范 → 告诉 AI "设计怎么做"

    而且 DESIGN.md 是跨工具的——Stitch、Claude Code、Gemini CLI、Cursor 都能用。

    DESIGN.md 格式

    一个典型的 DESIGN.md 包含以下几个部分：

    # 项目名 — Design System

## Colors

### Primary
- `#4361EE` — 主色（按钮、链接、强调）
- `#3A56D4` — 主色 Hover

### Neutral
- `#1A1A2E` — 文字主色
- `#F5F7FA` — 背景色
- `#FFFFFF` — 卡片/面板背景

### Semantic
- `#2EC4B6` — 成功
- `#FF9F1C` — 警告
- `#E71D36` — 错误

## Typography

- 标题: `Inter`, 600, 2rem/1.75rem/1.5rem/1.25rem
- 正文: `Inter`, 400, 1rem/0.875rem
- 代码: `JetBrains Mono`, 400, 0.875rem

## Spacing

- 4px / 8px / 12px / 16px / 24px / 32px / 48px / 64px

## Border Radius

- 按钮: 8px
- 卡片: 12px
- 输入框: 6px

## Shadows

- 卡片阴影: `0 2px 8px rgba(0,0,0,0.08)`
- 下拉菜单: `0 4px 16px rgba(0,0,0,0.12)`

## Components

### Button
- Primary: 背景 #4361EE, 文字白色, 圆角 8px, padding 12px 24px
- Secondary: 边框 1px solid #4361EE, 文字 #4361EE, 背景透明
- Ghost: 无背景无边框, 文字 #4361EE

### Input
- 边框: 1px solid #D0D0DD
- Focus: 边框 #4361EE, 阴影 0 0 0 3px rgba(67,97,238,0.15)
- 圆角: 6px

    三种使用方式

    方式 怎么做 适用场景
    1. 手动创建 + 上传 写一个 DESIGN.md 文件，在 Stitch 中通过设计系统面板导入 有现成设计规范的项目
    2. 从 URL 提取 Stitch 会自动分析任意网站的 CSS，提取配色和字体 参考竞品或灵感站点
    3. 从源码提取 使用 stitch::extract-design-md skill 从前端代码中自动提取 已有前端项目（和 Claude Code 配合使用）

    如何应用到屏幕

    有了 DESIGN.md 后，在 Stitch 中：

    1. 创建设计系统 — 在项目面板中导入或创建 DESIGN.md
    2. 应用到屏幕 — 选择目标屏幕，点击"应用设计系统"
    3. 生成时自动遵循 — 提示词中不再需要重复颜色/字体，只需说"按设计系统风格"
    💡 这就是 DESIGN.md 的威力：

    有了它后你的提示词可以简化为：

    按照当前设计系统，为 TaskFlow 生成一个用户设置页面
包含：个人资料编辑、密码修改、通知偏好

    不再需要写颜色、字体、间距——DESIGN.md 已经定义了。

    和 Claude Code 的联动

    Stitch 的 stitch::extract-design-md skill 可以从你现有的前端代码中自动提取 DESIGN.md 文件。 你在 Claude Code 中运行这个 skill，它分析你的 Tailwind 配置、CSS 变量、组件代码，生成一份完整的 DESIGN.md。

    • 然后把这份 DESIGN.md 导入 Stitch → 所有新设计自动遵循你现有的设计规范
    • 或者在 Stitch 中改完设计后导出 DESIGN.md → 让 Claude Code 更新前端代码的 CSS 变量
    💡 设计 ⇄ 代码 双向同步

    代码 → 设计：Claude Code 从源码提取 DESIGN.md → Stitch 导入 → 新设计遵循现有风格

    设计 → 代码：Stitch 改设计 → 导出 DESIGN.md → Claude Code 更新 CSS 变量

    这个双向流程是 Stitch + Claude Code 集成的核心价值，L5 会深入讲。

    动手练习

    🎯 练习：创建你的第一个 DESIGN.md

    场景：为你的个人项目创建一份设计系统文件。

    步骤：

    1. 用 Stitch 从 URL 提取

      在 Stitch 中新建项目 → 设计系统面板 → "从 URL 导入" → 输入你喜欢的网站（比如 linear.app 或 cal.com）

      Stitch 会自动分析它的配色和字体，生成一个初始 DESIGN.md。

    2. 手动调整

      修改 DESIGN.md，把你的品牌色加进去，调整你认为不合适的值。

    3. 应用到屏幕

      写一个提示词生成新屏幕，然后应用设计系统看看变化。

    4. 对比效果

      生成同一个页面：

      • 有 DESIGN.md 时："按设计系统生成登录页面"
      • 无 DESIGN.md 时：手动写所有颜色字体

      体验效率差距。

    相关 Skill

    Skill 名称 作用
    stitch::manage-design-system 上传 DESIGN.md 并将主题应用到屏幕
    stitch::extract-design-md 从前端代码中自动提取 DESIGN.md（需 Claude Code）
    design-md 分析 Stitch 项目并生成语义化的 DESIGN.md
    taste-design 生成实施"高级、反通用 UI 标准"的 DESIGN.md

    本课关键要点

    💡 核心记忆点
    • DESIGN.md = 设计系统的"代码化"标准，和 CLAUDE.md 是同一思路
    • 包含：颜色、字体、间距、圆角、阴影、组件规范
    • 三种使用方式：手动创建、从 URL 提取、从源码提取
    • 一次定义 → 所有屏幕、所有提示词自动遵循
    • 和 Claude Code 可以双向同步（设计 ⇄ 代码）

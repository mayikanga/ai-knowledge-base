    yt-dlp 原理

    一条下载命令背后发生了什么

    前两课你学会了怎么用 yt-dlp。这课拆开来看它里面是怎么工作的——从 URL 输入到文件落盘，每一层在干什么。 理解原理后你就能预测它的行为、排查复杂问题、以及为 agent 编写指令时不靠猜。

    下载一条视频的全链路

    你输入 yt-dlp "URL"
  ↓
① Extractor（提取器）——识别网站、抓取页面
  ↓
② Info Extraction（信息提取）——解析元数据
  ↓
③ Format Selection（格式选择）——按你的规则选最优
  ↓
④ Download（下载）——分片下载视频+音频
  ↓
⑤ Post-Processing（后处理）——合并、转码、嵌入字幕
  ↓
文件落盘

    Extractor（提取器）

    每个支持的网站都有一个对应的 Extractor 类，负责"理解这个网站"。yt-dlp 有 1800+ 个 Extractor。

    yt-dlp "https://www.youtube.com/watch?v=xxx"
        ↓
YouTube Extractor（提取器）
  ├─ 1. 下载网页 HTML
  ├─ 2. 提取页面中的初始数据（player response）
  ├─ 3. 解析视频标题、时长、缩略图、字幕、格式列表
  ├─ 4. 处理 JavaScript 加密参数（signature deciphering）
  └─ 5. 返回结构化的 info dict
    💡 为什么需要理解这个？

    下载失败时，90% 的问题出在 Extractor 阶段——网站改版了、Cookies 过期了、地理限制了。

    知道 Extractor 的步骤，你就知道该去查哪一步。

    查看 Extractor 输出（调试用）：

    yt-dlp --print-json "URL"
# 看到的是 Extractor 返回的原始 info dict

    Info Dict（信息字典）

    Extractor 的输出是一个结构化字典，包含视频的所有元数据。后面的所有阶段都依赖它：

    {
  "id": "dQw4w9WgXcQ",
  "title": "Rick Astley - Never Gonna Give You Up",
  "duration": 212,
  "uploader": "Rick Astley",
  "formats": [
    {
      "format_id": "137",
      "ext": "mp4",
      "width": 1920,
      "height": 1080,
      "vcodec": "avc1.640028",
      "acodec": "none",
      "filesize": 52517535,
      "tbr": 2200  // 总比特率 (kbps)
    },
    {
      "format_id": "140",
      "ext": "m4a",
      "acodec": "mp4a.40.2",
      "abr": 128,   // 音频比特率
      "filesize": 3473182
    }
  ],
  "subtitles": { "en": [...], "zh-Hans": [...] },
  "thumbnails": [...]
}

    关键字段：

    字段说明
    formats[]所有可用的画质/格式列表
    format_id格式唯一标识符（-F 显示的那个编号）
    height/width视频分辨率
    tbr总比特率（越高画质越好）
    vcodec/acodec视频/音频编码格式
    filesize文件大小（字节）
    abr音频比特率

    格式选择算法

    -f 参数不是简单的"选最高的"，而是经过多层排序：

    默认规则（不指定 -f）

    # 等价于
-f "bestvideo+bestaudio/best"
# 逻辑：
# 1. 尝试 bestvideo + bestaudio 分离下载 → ffmpeg 合并
# 2. 如果无法分离（或没装 ffmpeg），退回到 best（单个文件）

    -S 排序参数

    -S 自定义格式的排序规则，决定了在多个匹配的格式中选哪个：

    # 默认排序
-S "+size,+br"  # 文件大小从小到大，总比特率从小到大

# 按分辨率降序，偏好 av1 编码
-S "height:desc,codec:av01"

# 按文件最小 + 编码优先 vp9
-S "size:asc,codec:vp9"

# 不要 av1 编码（兼容性优先）
-f "bestvideo[height<=1080]+bestaudio/best" -S "codec:av01:murder"
    排序键说明
    height分辨率
    tbr/vbr/abr总/视频/音频比特率
    size文件大小
    codec编码格式（h264/av1/vp9）
    ext容器格式（mp4/webm）
    proto传输协议（https/dash/m3u8）
    br比特率（综合）

    下载与合并

    选定格式后，yt-dlp 下载视频和音频流（可能来自同一个文件，也可能是分离的两个流），然后用 ffmpeg 合并：

    情况 A：单一文件（如 720p mp4）
  └─ 直接下载，保存

情况 B：分离流（如最佳视频 [无音频] + 最佳音频）
  ├─ 下载 video.mp4（仅画面）
  ├─ 下载 audio.m4a（仅声音）
  └─ ffmpeg -i video.mp4 -i audio.m4a -c copy output.mp4
      （ffmpeg 把它们封装进同一个容器）

情况 C：DASH 分片流
  └─ 每个视频和音频被切成 N 个小片
  ├─ 并行下载所有分片
  └─ 合并分片 → 合并音视频

    后处理管线

    下载完成后，yt-dlp 按顺序执行后处理器：

    下载完成 → 后处理器链（可自由组合）：

  Step 1: 嵌入缩略图（--embed-thumbnail）
  Step 2: 嵌入字幕（--embed-subs）
  Step 3: 嵌入元数据（--embed-metadata）
  Step 4: 转码/提取音频（-x --audio-format mp3）
  Step 5: 重命名（-o 模板）

每个步骤都可选，按你在命令行指定的顺序执行。

    配置优先级

    理解配置加载顺序，才能写不出 bug 的自动化脚本：

    优先级从高到低：
  1. 命令行参数           — 最高，覆盖一切
  2. 本地配置文件         — 当前目录的 yt-dlp.conf
  3. 用户配置文件         — ~/.yt-dlp/config（或 %APPDATA%/yt-dlp/config.txt）
  4. 系统配置文件         — /etc/yt-dlp.conf
  5. 内置默认值           — 最低

    后面层级的同名参数被前面层级覆盖。多条不同参数则合并。

    原理对 agent 的意义

    理解了这些，你就能给 agent 写清晰的指令而不用碰运气：

    场景agent 需要知道的原理
    "下载最好的视频"格式选择算法 → 知道用 -f bestvideo+bestaudio/best
    "出错时重试"Extractor 流程 → 知道先加 cookies
    "下载后自动转 MP3"后处理管线 → 知道用 -x --audio-format mp3
    "批量处理"info dict → 知道怎么解析输出来编排工作流

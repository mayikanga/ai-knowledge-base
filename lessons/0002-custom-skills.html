Lesson 2 / 6

    Custom Skills

    把你的工作流打包成可复用的指令包

    Mission 关联：上一课你学会了让 Claude Code自动执行操作（hooks）。这一课你将学会把重复性的提示词和流程打包成 一个 /你的命令 —— 再也不用每次都手打一整段需求了。

    什么是 Skill？

    Skill 是 Claude Code 的可复用指令包。一个 Skill 就是一个 SKILL.md 文件（以及可选的附属文件）， 它教会 Claude 如何完成某个特定领域任务，并暴露为 slash command 供你随时调用。

    💡 Skill vs. CLAUDE.md
    CLAUDE.md 是每次会话都加载的全局指令 —— 像操作系统的常驻进程。
    Skill 是按需调用的指令包 —— 像你在终端里敲的一个命令。只在需要时消耗上下文。

    Skill 的存放位置

    位置 作用域 特点
    ~/.claude/skills/<name>/SKILL.md 全局（所有项目） 你的个人技能库，走到哪用到哪
    .claude/skills/<name>/SKILL.md 项目级别 可提交到仓库，团队共享
    commands/<name>.md 单文件版（旧格式） 功能相同，但没有多文件结构。推荐用技能格式
    📁 目录结构示例： 
    .claude/skills/
  deploy/
    SKILL.md        ← 核心指令文件
    reference/       ← 附属参考文件
    templates/       ← 模板
  code-review/
    SKILL.md

    SKILL.md 的 Frontmatter

    SKILL.md 的开头是 YAML frontmatter（--- 包裹），定义了 skill 的元数据：

    字段 必填？ 说明 示例
    name ✅ Skill 名称，也是 /name 的命令名 deploy
    description ✅ 一句话描述何时使用。Claude 据此自动发现和调用 Deploy the app to production
    args ❌ 定义参数名、类型、是否必填 [{name: "env", required: true}]
    allowedTools ❌ 允许使用的工具列表（免权限提示） ["Bash", "Read", "Edit"]
    disallowed-tools ❌ 拒绝使用的工具（v2.1.202+） ["Write"]
    context ❌ 设为 fork 在隔离 subagent 中运行 fork
    model ❌ 覆盖会话的模型设置 sonnet
    user-invocable ❌ 设为 false 只做后台知识，不暴露为命令 true
    disable-model-invocation ❌ 设为 true 阻止 Claude 自动调用 false
    hooks ❌ 作用域限定到此 skill 的 hooks PreToolUse: ./skill-hooks/pre-check.sh

    SKILL.md 的内容部分

    frontmatter 之后就是 markdown 正文，告诉 Claude 具体怎么做。你可以用一些特殊的语法：

    参数引用

    在命令体中使用 $ARGUMENTS 接收用户输入的参数：

    ---
name: blog-outline
description: "Create a structured blog outline"
args:
  - name: topic
    required: true
  - name: audience
    required: true
---
You are a blog outline creator.

Topic: $ARGUMENTS[1]
Audience: $ARGUMENTS[2]

Follow these steps:
1. Read any style guides in /guides/
2. Propose a 6-8 section outline with H2s and 2-3 bullets per section
3. Save the outline to drafts/<slug>-outline.md

    然后你就可以这样调用：

    /blog-outline topic="Claude Code tips" audience="developers"

    Shell 注入

    用 ! 包裹的命令会被执行并将输出注入到 skill 的上下文中：

    当前分支是：!git branch --show-current!
    ⚠️ 注意：Shell 注入在 skill 加载时执行，输出会直接变成 prompt 的一部分。

    三种 Skill 类型

    类型 用途 示例
    Reference Skill 提供知识给 Claude，不主动干活 API 风格指南、项目约定
    Action Skill 执行特定操作流程 /deploy 执行部署检查清单
    Bundled Skill 插件自带的技能包 从市场安装的插件中的 skill

    user-invocable: false + disable-model-invocation: true 的 skill 就是纯 Reference Skill——提供知识但不暴露为命令。

    Skill 的调用方式

    1. Slash command：/skill-name arg1="value"
    2. 自动发现：Claude 在会话启动时加载所有 skill 的 description，当任务匹配时自动调用
    3. Skill Stacking（v2.1.199+）：多个技能同时激活

    动手练习：创建一个实用的 Skill

    🎯 练习：写一个 /git-cleanup Skill

    场景：你经常需要清理已合并的 Git 分支。把这个流程打包成一个 skill：

    步骤：

    1. 创建目录结构

      在 ~/.claude/skills/ 下创建 git-cleanup/SKILL.md：

      mkdir -p ~/.claude/skills/git-cleanup
    2. 编写 SKILL.md 
      ---
name: git-cleanup
description: "清理已合并的本地 Git 分支，保持仓库整洁"
allowedTools: ["Bash"]
---

# Git 分支清理助手

当前仓库路径：!pwd!

## 步骤

1. 先运行 `git fetch --prune` 同步远程分支状态
2. 列出已合并到主分支的本地分支：
   `git branch --merged main | grep -v "main\|master"`
3. 逐个确认后删除（用 `git branch -d`）
4. 最后运行 `git remote prune origin` 清理远程追踪引用

## 注意事项

- 永远不要删除当前所在分支
- 优先用 `-d`（安全删除），不要用 `-D`（强制删除）
- 删除前先问用户确认
    3. 测试

      在任意 git 仓库中启动 Claude Code，输入 /git-cleanup。看到 Claude 按你的 skill 执行了吗？

    4. 改进：加上参数

      试试加上 args 让用户指定目标分支：

      args:
  - name: target-branch
    required: false
    default: main

      然后在正文中用 $ARGUMENTS[1] 或 $1 引用。

    Skill 的最佳实践

    • description 要精准 —— Claude 根据它决定何时自动调用。模糊的描述 = Claude 在不该调的时候乱调
    • 能用 context: fork 就用 —— 避免 skill 的输出污染主会话上下文
    • 限定 allowedTools —— 按最小权限原则，只给 skill 需要的工具
    • 先手动测试 —— 用 /name 调通后再信赖自动发现
    • 附带参考文件 —— 把大段知识放到 skills/name/reference/ 下，正文保持简洁

    Reference Skill vs. Action Skill

    两种 skill 的区别就在 frontmatter 的两个字段上：

    # ── Action Skill（用户可调用）──
name: deploy
description: "Deploy the app"
user-invocable: true
# ── Claude 也可能根据 description 自动触发 ──

# ── Reference Skill（仅后台知识）──
name: api-style
description: "API design conventions for this project"
user-invocable: false
disable-model-invocation: true
# ── 只提供知识，不出现在 slash commands 里 ──
    💡 学到了什么？
    • Skill 的本质：可复用的指令包，按需调用
    • SKILL.md 的 frontmatter 全部字段及含义
    • 参数引用（$ARGUMENTS）和 Shell 注入（!command!）
    • 三种 skill 类型：Action / Reference / Bundled
    • 本地 vs 项目级 skill 的存放位置
    • Skill Stacking（多技能同时激活）
    • 最佳实践：最小权限、fork 隔离、精准 description

    额外挑战：skill + hook 联动

    还记得上节课的 hooks 吗？Skill 的 frontmatter 也可以声明 hooks：

    ---
name: dangerous-task
hooks:
  PreToolUse: ./skill-hooks/extra-check.sh
---
# 某个可能危险的任务...

    这意味着你可以给特定的 skill 加上额外安全检查，而不影响全局的 hook 配置。试试把你上节课的"破坏性操作守卫"绑定到某个特定 skill 上？

    实战整合

    构建你的开发助手

    Mission 关联：这是最后一课。你把前五课学到的全部知识——hooks、skills、subagents、workflows、高级模式——全部用到同一个真实项目中。 完成后你拥有一个可投入日常使用的"开发助手"系统。

    项目概览

    我们将为你的项目搭建一个完整的 Claude Code 开发助手，包含：

    组件 来源课程 作用
    .claude/CLAUDE.md L1-L6 基础 项目上下文、编码规范
    .claude/settings.json L1 权限 + 全局安全 hooks
    .claude/skills/review/SKILL.md L2 /review 一键代码审查
    .claude/agents/reviewer.md L3 专业的代码审查 subagent
    .claude/workflows/full-audit.js L4 多 agent 编排：安全+性能+质量
    Build Order L5 确保安装顺序正确
    🎯 目标

    完成后你可以做这些事：

    • 输入 /review → 一键审查当前变更
    • 输入 /full-audit → 并行跑安全/性能/质量审查
    • 危险操作（rm -rf、git push --force）→ hook 自动拦截
    • 每次编辑后 → hook 自动格式化

    第一步：Foundation（地基）

    创建项目级别的 .claude/ 目录和 CLAUDE.md：

    mkdir -p .claude

    写入 .claude/CLAUDE.md：

    # 项目指令

## 技术栈
- 语言/框架：[你的技术栈]
- 构建工具：[你的构建工具]
- 测试框架：[你的测试框架]

## 编码规范
- 使用 [你的代码风格]
- 测试覆盖率要求：核心逻辑 > 80%
- 所有公开函数必须有 JSDoc/类型注解

## 工作流
- 提交前必须通过 lint 和测试
- 敏感信息永远不要硬编码
- TypeScript 优先于 JavaScript

## 关键路径
- src/ 核心源码
- tests/ 测试文件
- docs/ 文档

    把 [方括号] 内容替换成你项目的实际情况。

    第二步：Core Tooling（基础设施）

    创建 .claude/settings.json，配置权限和安全 hooks：

    {
  "permissions": {
    "allow": [
      "Bash(command: *npm*)",
      "Bash(command: *git*)",
      "Bash(command: *node*)",
      "Bash(command: *python*)",
      "Bash(command: *npx*)",
      "Read",
      "Write",
      "Edit",
      "Glob",
      "Grep"
    ]
  },
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "node -e \"
  const input = require('fs').readFileSync('/dev/stdin','utf8');
  const cmd = JSON.parse(input).tool_input?.command || '';
  const blocked = ['rm -rf /', 'git push --force', 'DROP TABLE'];
  if (blocked.some(b => cmd.includes(b))) process.exit(2);
\"",
            "timeout": 5
          }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "echo '文件已修改，手动运行格式化命令：npx prettier --write'",
            "timeout": 5
          }
        ]
      }
    ]
  }
}
    ⚠️ 注意：permissions 的 allow 规则根据你的实际项目工具调整。如果你用 pnpm 替换掉 *npm*。 也可以安装 fewer-permission-prompts skill 来自动优化。

    第三步：Custom Skill（复用）

    创建 .claude/skills/review/SKILL.md：

    ---
name: review
description: "Review recent code changes for quality and correctness"
allowedTools: ["Bash", "Read", "Grep", "Glob"]
---

# 代码审查助手

当前仓库：!git rev-parse --show-toplevel!

## 步骤
1. 运行 `git diff --stat` 了解变更概览
2. 审查每个变更文件：
   - 逻辑是否正确
   - 是否有安全隐患
   - 是否符合项目编码规范
   - 是否有测试覆盖
3. 输出审查报告，按严重度排序

## 输出格式
- [严重度: 高/中/低] 问题描述
- 位置: 文件名:行号
- 建议: 修改方案

    测试：在项目目录中运行 /review。

    第四步：Custom Subagent（分工）

    创建 .claude/agents/reviewer.md：

    ---
name: reviewer
description: "Review code for correctness, security, and style - PROACTIVELY"
tools: Read, Grep, Glob, Bash
disallowedTools: Write, Edit
model: haiku
permissionMode: acceptEdits
maxTurns: 15
color: green
---

你是一个资深的代码审查专家。

## 审查维度
1. 正确性：逻辑是否完备，边界情况是否处理
2. 安全性：是否有注入、泄露、权限漏洞
3. 可维护性：命名、结构、注释是否清晰

## 约束
- 只读代码，不改代码
- 每个问题标注严重度
- 最后给出总体评分 1-10

    测试：在对话中输入 @reviewer 审查这个 PR 的变更。

    第五步：Workflow（编排）

    在 Claude Code 中执行以下命令来创建 workflow：

    /workflows

    然后告诉 Claude：

    帮我创建一个 workflow，对当前代码变更做三方面审查：安全性、性能、代码质量。 三个审查并行进行，结果汇总成一份报告。保存到 .claude/workflows/full-audit.js。

    Claude 会生成脚本并运行。如果没问题，它会自动保存。
    之后在任何项目中，输入 /full-audit 就可以一键审查。

    验证清单

    完成后逐项验证：

    # 验证项 怎么做 预期结果
    1 CLAUDE.md 生效 启动 Claude Code，让它写一段代码 代码风格符合 CLAUDE.md 定义
    2 Hook 拦截危险命令 让 Claude 运行 rm -rf / 被阻止，不会真正执行
    3 Skill 可调用 输入 /review 按 skill 步骤执行审查
    4 Subagent 可调用 输入 @reviewer 审查这段代码 subagent 只读代码并输出审查
    5 Workflow 可运行 输入 /full-audit 多 agent 并行审查并汇总报告

    常见问题

    问题 排查
    /review 找不到 检查 .claude/skills/review/SKILL.md 路径是否正确，frontmatter 的 --- 是否闭合
    @reviewer 不触发 检查 .claude/agents/reviewer.md 的 name 字段与文件名一致
    Hook 不生效 检查 settings.json JSON 格式是否正确，可以用 node -e "JSON.parse(fs.readFileSync('.claude/settings.json'))" 验证
    settings.json 修改后不生效 Claude Code 会自动热加载，但如果没生效，重启会话
    Workflow 保存失败 确保 .claude/workflows/ 目录存在，且有写权限
